# SOZDATEL

Сайт-визитка студии: автоматизация бизнес-процессов, сайты и лендинги,
Telegram-боты, интеграции, дэшборды. Плюс закрытый личный кабинет владельца
с заявками, графиком и панелью Instagram.

Стек: Vite + React 18 + TypeScript + Tailwind + shadcn/ui + framer-motion + recharts.

## Запуск

```
npm install
npm run dev
```

Откроется на `http://localhost:5180`.

Сборка продакшена — `npm run build`, посмотреть результат — `npm run preview`.

## Заявки — как подключить приём (Supabase)

Заявки должны попадать в `/dashboard`, а не только в почту. Форма
(`src/components/features/ContactForm.tsx`) сохраняет заявку через
`src/lib/leads.ts`: если заданы `VITE_SUPABASE_URL` и
`VITE_SUPABASE_ANON_KEY` — идёт `insert` в таблицу `leads` в Supabase, и
`/dashboard` читает оттуда же (селект по анонимному ключу, обновление раз в
20 секунд). Без этих переменных — старый режим: всё в `localStorage`
браузера клиента, в кабинете не видно.

### Настройка (один раз)

1. Завести проект на supabase.com — бесплатный тариф, карта не нужна.
2. В SQL Editor выполнить:

   ```sql
   create table leads (
     id uuid primary key default gen_random_uuid(),
     name text not null,
     contact text not null,
     task text not null,
     status text not null default 'new',
     created_at timestamptz not null default now()
   );

   alter table leads enable row level security;

   -- Форма на сайте может создавать заявки
   create policy "anyone can insert leads"
     on leads for insert
     to anon
     with check (true);

   -- Кабинет может читать и менять заявки
   create policy "anyone can read leads"
     on leads for select
     to anon
     using (true);

   create policy "anyone can update leads"
     on leads for update
     to anon
     using (true);

   create policy "anyone can delete leads"
     on leads for delete
     to anon
     using (true);
   ```

3. В Project Settings → API скопировать `Project URL` и `anon public` ключ.
4. Вписать их в `.env` (или в секреты репозитория для GitHub Pages деплоя) —
   `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`.

**Важно про безопасность:** `anon`-ключ по дизайну Supabase публичный — он
всё равно попадёт в JS-бандл сайта (это нормально и для insert безопасно).
Но политика `select` выше открыта для любого, у кого этот ключ есть, — то
есть теоретически кто угодно, разобрав бандл, сможет прочитать список
заявок (имена, контакты, задачи) напрямую через Supabase REST API, в обход
сайта. Для входа в кабинет сейчас используется пароль на клиенте (см. ниже,
раздел «Логин»), а не настоящий Supabase Auth — поэтому сузить `select` до
`authenticated` пока нельзя, некому будет аутентифицироваться. Если это
важно — следующий шаг: подключить Supabase Auth по инструкции ниже, потом
заменить политику `select` на `to authenticated`.

### Formspree — дублирующее уведомление на почту (опционально)

Помимо Supabase, форма может параллельно слать те же данные POST-запросом на
Formspree — просто как уведомление на почту, отдельно от основного приёма.
Endpoint уже указан в `.env.example` как `VITE_LEAD_FORMSPREE_URL`. Ничего
регистрировать не нужно, если эндпоинт уже есть. Прочитать заявки обратно
через API Formspree не даёт — это платная фича, поэтому он не подходит как
основной канал для `/dashboard`.

Есть и старый `VITE_LEAD_WEBHOOK_URL` (для n8n) — работает так же, письмо не
шлёт, просто POST на произвольный адрес, если он у вас поднят.

Публичная версия сайта (без личного кабинета и внутренних деталей моста)
лежит отдельно и задеплоена на GitHub Pages — см. `.site-deploy/` и
`.github/workflows/deploy.yml` в этой же папке для актуального workflow.

## Логин: почему это не защита

Вход сравнивает пароль **прямо в браузере**. Vite подставляет `VITE_`-переменные
в собранный бандл как обычный текст — любой человек откроет DevTools → Sources,
найдёт строку с паролем и войдёт. Плюс сам флаг входа лежит в `localStorage`,
и его можно проставить руками.

То есть: это заглушка, чтобы кабинет не открывался случайному посетителю.
**Настоящей защиты здесь нет и быть не может** — проверка пароля на клиенте
защитой не бывает в принципе.

Для реальной защиты нужен бэкенд. Самый быстрый путь — Supabase Auth:

1. Завести проект на supabase.com, включить Email-провайдера, создать себе пользователя
2. `npm i @supabase/supabase-js`, положить URL и anon-ключ в `.env`
3. В `src/lib/auth.ts` заменить тела трёх функций — места помечены `TODO(auth)`:
   - `signIn` → `supabase.auth.signInWithPassword(...)`
   - `isAuthenticated` → `supabase.auth.getSession()`
   - `signOut` → `supabase.auth.signOut()`
4. После этого `localStorage`-флаг не нужен: сессию держит Supabase

Проверка в `src/components/layout/ProtectedRoute.tsx` при этом менять не нужно —
она уже опирается на `isAuthenticated()`.

## Живой экран браузера (кабинет)

`/dashboard` больше не показывает виджеты (статистика, график, заявки,
Instagram-панель) — вместо них один большой живой экран управляемого браузера
OpenClaw (профиль `openclaw`), в котором владелец залогинен в Instagram.
Компоненты виджетов никуда не делись (`src/components/features/dashboard/`),
просто не используются в `src/pages/Dashboard.tsx` — можно вернуть при желании.

Компонент экрана — `src/components/features/dashboard/LiveBrowserScreen.tsx`
(canvas + мышь/клавиатура). Как это работает и почему нельзя проще —
в `src/lib/auth.ts` соседний пример неприменим, смотрите ниже.

### Почему через мост, а не напрямую

Из фронта нельзя подключиться к CDP (`http://127.0.0.1:18800`) напрямую:
Chrome отклоняет WebSocket-апгрейд, если в заголовке `Origin` что-то есть, а
браузер всегда его шлёт. Поэтому `sozdatel-server.py` держит второй сервер —
WebSocket-мост на `ws://127.0.0.1:3724`, который:

- находит вкладку Instagram среди открытых (`/json/list`), а если её нет —
  берёт первую открытую страницу;
- **активирует** найденную вкладку (`/json/activate/<id>`) — Chrome не шлёт
  кадры скринкаста для вкладок не в фокусе, без активации поток молчит без
  единой ошибки;
- шлёт `Page.startScreencast` и пересылает кадры во фронт, обязательно
  отвечая `Page.screencastFrameAck` на каждый — иначе поток встаёт после
  первых же кадров;
- принимает клики/скролл/клавиатуру от фронта и шлёт их в CDP
  (`Input.dispatchMouseEvent` / `Input.dispatchKeyEvent`).

Оба сервера (статика на 3723 и мост на 3724) слушают только `127.0.0.1`.
**Так и должно оставаться** — в кабинете залогиненный Instagram владельца,
наружу это выставлять нельзя.

### Зависимость: пакет `websockets`

`http.server`, на котором сидела статика, WebSocket не умеет — добавлен
пакет `websockets` (только для моста, фронту ничего ставить не надо).

Автозапуск (`~/Library/LaunchAgents/com.pixelhq.sozdatel.plist`) использует
`/usr/local/bin/python3.12` — пакет должен стоять именно там:

```
/usr/local/bin/python3.12 -m pip install --user --break-system-packages websockets
```

`--break-system-packages` нужен, потому что этот Python управляется Homebrew
(PEP 668) — флаг ставит пакет в пользовательский site-packages, брузер и
систему не трогает.

### Если экран не показывает картинку

Управляемый браузер должен быть поднят: `openclaw browser --browser-profile
openclaw start`. Компонент сам покажет понятное сообщение и кнопку «Повторить»,
если CDP недоступен или в браузере нет открытых вкладок — но поднять сам
браузер он не может, это делает BRAIN.

## Instagram: что можно и что нельзя

Раздел ниже — про `InstagramPanel.tsx`, сейчас не используется в кабинете
(см. секцию про живой экран выше), но код рабочий и его можно вернуть.

### Нельзя: встроить Instagram целиком

Открыть instagram.com внутри кабинета и залогиниться там **невозможно**.
Instagram отдаёт заголовки `X-Frame-Options` и CSP `frame-ancestors`, которые
запрещают показывать его сайт в рамке на чужом домене. Сделано это специально —
защита от фишинга, чтобы никто не подсовывал поддельное окно входа. Обхода нет,
и любой «способ» это обойти — либо не работает, либо ворует ваш пароль.

Поэтому в панели стоят кнопки, открывающие Instagram в новой вкладке: лента,
профиль и сообщения.

### Можно: показывать свои посты

Панель рисует ваши публичные посты и reels штатным встраиванием Meta
(`blockquote.instagram-media` + `//www.instagram.com/embed.js`). Токен для этого
не нужен.

Чтобы включить:

1. Открыть `src/data/instagram.ts`
2. Вписать свой ник в `username` (без «@»)
3. В `postUrls` добавить ссылки на посты: в Instagram открыть пост → «…» →
   «Копировать ссылку»

Ограничение: работают только **публичные** посты. Если аккаунт закрыт,
Instagram отдаст пустые блоки — сначала откройте профиль.

### Метрики: как включить настоящие

Подписчиков, охваты и показы встраивание не отдаёт — их даёт только
**Instagram Graph API**. Instagram Basic Display API окончательно выключен
4 декабря 2024 года, так что это единственный путь.

Что для этого нужно:

1. Перевести аккаунт в **Business** или **Creator** (Настройки → Тип аккаунта)
2. Привязать его к странице Facebook
3. Создать приложение на developers.facebook.com, добавить продукт
   Instagram Graph API
4. Получить **долгоживущий токен** (60 дней, продлевается)
5. Поднять серверный эндпоинт-прокси, который держит токен у себя и отдаёт
   фронту готовые цифры

Пятый шаг обязателен: **токен нельзя класть во фронтенд**. Всё, что попало в
`.env` с префиксом `VITE_`, оказывается в бандле и становится публичным —
токен утечёт в первый же день.

Когда прокси появится — указать его адрес в `PROXY_URL` в
`src/lib/instagramGraph.ts` и заменить тело `fetchProfileStats` реальным
запросом (заготовка и пример кода в комментариях того же файла).

Пока Graph API не подключён, панель честно показывает «метрики не подключены».
Выдуманных цифр в интерфейсе нет — и не должно появиться.
